# Next milestone: private company workspaces and test-mode Team subscriptions

**Base:** the reviewed/merged Prompt 1 changes. **Outcome:** two authorized people can collaborate on the same durable investigation; another company cannot access its records or files. A successful test-mode entitlement enables a Team workspace. Prompt 1 does not meet this release gate.

Implement these in order. Prefer managed PostgreSQL, managed authentication, and private object storage (Supabase is the default candidate; verify current provider documentation and requirements at implementation time).

- [ ] **Organizations and membership:** organizations, sites, teams, memberships, invitations, revocation, and a written role matrix. Separate authentication, membership, record permissions, reviewer approval authority, and paid entitlements. Suggested roles: org owner/billing admin, team manager, collaborator, assigned-action participant/reporter, viewer. Define who can invite, export, delete, approve, and bill before policies.
- [ ] **Trusted shared storage:** server-side persistence for Problem/Investigation, Evidence, Cause, Action, Verification, Lesson, MetricObservation, Attachment, and AuditEvent. Require same-organization composite references on every relationship. Reuse domain guards on the server. Enforce tenant and role policies at the database and API boundary, not in UI controls.
- [ ] **Concurrency and audit:** revision/optimistic-lock checks with visible conflicts; no last-writer-wins data loss. Append authenticated actor, command, record, timestamp, prior/new revision, and approval changes to protected audit history. Keep sensitive text out of telemetry. Controlled background work uses a durable outbox with idempotent jobs; no agent execution.
- [ ] **Private files and recovery:** validate file type/size; authorize upload, download, signed links, search, exports, and jobs. Keep attachments private. Define retention/deletion behavior for active records, objects, derived indexes, and backups. Perform and record an actual restore of **records and attachment bytes**, including permissions and source relationships; specify measured recovery limits.
- [ ] **Explicit local import:** user chooses local exports/documents, reviews a manifest and destination company, resolves validation/closure issues, maps local names to members, and confirms upload. Preserve local originals, source IDs, checksums, schema version, and an import manifest. Allocate hosted IDs, remap all relationships transactionally, import attachment bytes explicitly, and make retries idempotent. Verify counts/checksums in the destination before offering local cleanup. Never auto-upload or auto-delete.
- [ ] **One Team plan in test mode:** server-configured planning default $299/month, one team workspace at one site, 10 full collaborators. Define lightweight internal reporting/viewing and assigned-action participation without a reporter fee. Enforce limits on the server. Implement test checkout, billing management, signed webhook verification, reconciliation, duplicate/out-of-order events, retries, failed payment, cancellation, and a documented read-only/export grace period. The checkout redirect is never payment authority.
- [ ] **Release evidence:** two organizations and multiple roles; guessed/mixed-tenant IDs, revoked memberships, attachment links, search/export, jobs, stale writes, invalid closure transitions, and all subscription lifecycle edges. Two-user collaboration must show durable shared state. A missing provider configuration must show unavailable, never silently fall back to browser memory. Update Trust/privacy/setup docs only with demonstrated behavior.

**A paid pilot is gated on all of the above**, plus human review of security, recovery evidence, and test billing behavior. No production migrations, paid resources, real invitations, or live charges are authorized by this checklist. Plant/Enterprise plans, annual plans, agent add-ons, LLM calls, and autonomous actions remain later work.
