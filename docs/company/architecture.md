# Company architecture decisions

## One authoritative command boundary

The investigation aggregate is the smallest transactional unit. `company.investigations` holds a versioned HostedDocument and optimistic integer revision. Its node/edge index gives Investigation, Evidence, Cause, Action, Verification, VerificationReview, Lesson, MetricObservation, Attachment and the associated history stable UUIDs and same-organization/investigation composite foreign keys. Sites and teams are explicit and each has a unique organization constraint. There is no second Results or Lessons database and no workflow engine. Local process-map references are retained only as untrusted import provenance; hosted process maps are deferred rather than allowing a foreign/local map ID into company data.

Business commands are a strict Zod discriminated union. Generic patches, document replacement, actor/approval/audit fields, client timestamps and snapshots are not accepted. An authenticated server request obtains current membership, takes a per-organization advisory transaction lock (also used by invitations, membership and billing), checks the expected record revision and idempotency receipt, runs the existing Solve reducer plus hosted dependencies, then commits aggregate, indexes, audit, receipt and outbox together. The database login is not a table owner and cannot bypass RLS; browser roles have no mutation grants. Idempotent retries return authoritative current state, not an old copy. A reused key with a different actor or body is rejected.

## Explicit trusted decisions

The server supplies authenticated reviewer identity and server decision time. It builds the merged domain snapshot and stores hosted dependencies on the exact review: relevant file IDs, immutable object-version IDs, verified SHA-256, source state, and linked measurement units/periods/values. Domain material edits, hosted observations and file changes invalidate affected approval without deleting it. Edit-and-revert cannot revive a decision. Reopening binds deliberate re-review to an event ID; generic timestamps cannot satisfy it, and valid observation periods can be reused.

The merged per-action blocker rule is retained. Another action's missing assignment/result does not prevent this action's approval; shared root/containment rules still apply. Closure checks every required action. Effective without explicit current approval, monitoring, and partial effectiveness stay open. Lesson decisions retain their exact supporting review; new reviews never silently reapprove old lessons. Lesson text edits clear current approval while lessonDecisions preserve the decided text and source relationship.

Staging a file withdraws affected approval because the new source is incomplete. Finalization reads back the stored bytes before committing a checksum. Explicit file removal withdraws affected approval and revokes downloads immediately. Approval/closure/lesson approval rechecks ready source bytes. Missing or mismatched bytes block approval/download/export; “Check stored source files” persists a missing state and approval invalidation. Provider-admin changes are detected on these checks, not by an advertised continuous scanner. Files are never rendered inline or overwritten in place.

## Save, import, and authorization boundaries

The company editor uses command submission and confirmed database receipts, separate from the browser-local DocumentProvider. In-memory drafts remain visible during failures. Navigation and Duplicate flush the current form and stop on failure or unfinished selected uploads. Conflicts offer “Load latest; keep my draft,” disabling Save during reload and requiring deliberate reconciliation. Recovery export retains repeated form entries and selected upload bytes. First-problem drafts survive internal view changes in memory, scoped by company, with explicit recovery/discard controls and a page-exit guard. There is no hidden localStorage/IndexedDB company copy. Public demo/local regression tests remain required.

Shared views load 100 investigations at a time with an explicit older-record control. The assigned-work view shows work from the loaded investigations and makes that limit visible when more exist; changing to Actions/Results/Lessons clears a Problems search filter. Reload reconciles the list after concurrent changes. This is a small-team aggregate model, not a large-tenant search engine.

Import starts with a client-side manifest and named destination. Server validation checks references and name mappings again on confirmation, allocates UUIDs, remaps relationships, and transactionally inserts the aggregate/index/audit/receipt. Provenance retains original IDs, schema version, original parsed JSON and SHA-256 of its JSON serialization. This checksum describes imported content, not original whitespace/encoding. Local decisions and map links stay untrusted provenance. File references remain unresolved until the user stages/finalizes the original bytes; originals are never deleted. Hosted Duplicate follows the same deliberate-review rule.

Billing-admin privileges, reviewer authority and subscription entitlements remain independent. Participant scope is defined in the permission matrix. All current members have internal team visibility; external scoped guests are not implemented. Record search, export, downloads and queued work reauthorize current membership. Realtime is disabled, so there is no stale-authority subscription channel. Company routes suppress attribution, analytics and speed-insight collection. API responses use no-store and expose sanitized errors rather than SQL, credentials or evidence text.

## Audit and asynchronous work

Application audit records actor (null for verified Stripe service events), server timestamp, command ID/name, record, prior/new revisions, correlation ID, versioned provenance, and approval/invalidation events. Ordinary application roles cannot update/delete audit. Database operators can alter the system: this is **not** a cryptographic signature, tamper-proof ledger, certification or independently notarized record. Auth audit is a separate provider facility.

Contract v1 command: `{version, organizationId, commandId, recordId, expectedRevision, correlationId, command}`. Actor and provenance are resolved on the server. Outbox v1: `{id, org_id, actor, command_id, record_id, expected_revision, correlation_id, version, kind, payload}`. The transaction writes required events; the consumer rechecks initiating membership/capability and relevant record revision. `record_changed` is an idempotent acknowledgement-only consumer today. Invitation and deletion jobs retry from the same outbox row. SMTP may redeliver the same Message-ID/link if a send succeeds before receipt commits; no second invitation membership/seat operation is created. Tokens are removed from completed outbox payloads.

## Future private Nostr adapter

Keep database/application authority. A future verified event maps to a scoped, revocable service identity, carries v1 IDs/revision/correlation/provenance, and enters the same command path. A signature establishes key control; current membership/policy determines permission. Sensitive evidence stays in private storage, not relay payloads. An agent must not inherit reviewer authority or bypass company checks. Relays, keys, wallets, public events, LLM calls, execution and autonomous external actions are intentionally absent.
